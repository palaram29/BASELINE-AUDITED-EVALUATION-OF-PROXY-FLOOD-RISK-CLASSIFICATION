# ML Model Evaluation — Methodology, Results, and Limitations

This document explains the model comparison results honestly, including why
headline accuracy is very high and what that does and doesn't mean. It's
written to be adapted directly into the dissertation's methodology / results
/ limitations sections.

---

## 1. Setup

Three algorithms — Random Forest, XGBoost, LightGBM — were trained and
compared under identical conditions:

- **Dataset**: `train_dataset.csv` (103,194 rows) / `test_dataset.csv`
  (44,226 rows), covering 30 Sri Lankan cities, 2010–2023.
- **Features** (identical for all three models): `City`, `Rainfall_3Day`,
  `Avg_Temperature`, `Avg_WindSpeed`, `Elevation`.
- **Target**: `Flood_Risk` ∈ {Low, Medium, High, Extreme}.
- **Selection metric**: weighted F1 Score (configurable).

## 2. Headline results

| Model | Accuracy | Weighted F1 | Macro F1 | ROC-AUC | Train Time | Predict Time |
|---|---|---|---|---|---|---|
| **Random Forest** ✅ | 99.94% | 99.94% | **~94-95%*** | ~100% | ~3-5s | ~60-150ms |
| XGBoost | 99.81% | 99.81% | **~92%*** | ~100% | ~0.4-1.5s | ~25-80ms |
| LightGBM | 99.05-99.89%* | 99.05-99.89%* | **~77-97%*** | 0.51-0.9999* | ~3-5s | ~50-200ms |

Random Forest was selected as the best model (highest weighted F1) in every
run. \*LightGBM's macro-F1 and ROC-AUC vary significantly depending on
whether class-balanced sample weighting is applied during training (see
§3.4) — with weighting: ROC-AUC ~0.9999, macro-F1 ~97%; without: ROC-AUC
~0.51-0.85, macro-F1 ~77%. Random Forest and XGBoost are comparatively
insensitive to this setting.

**Note the gap between Weighted F1 and Macro F1.** Weighted F1 is dominated
by the "Low" class, which is ~99.5% of the data. Macro F1 (the unweighted
average across all four classes) is the more honest measure of how well the
model handles the classes that actually matter for a flood warning system —
and it is visibly lower, especially for LightGBM without weighting.

## 3. Why accuracy is this high: the dataset, not the models

### 3.1 Severe class imbalance

| Class | Train rows | % of train |
|---|---|---|
| Low | 102,674 | 99.5% |
| Medium | 425 | 0.41% |
| High | 87 | 0.08% |
| Extreme | 8 | 0.008% |

A classifier that always predicts "Low" would already score ~99.4% accuracy
without learning anything. This alone explains most of the headline number.

### 3.2 The label is nearly a deterministic function of one feature

A trivial rule using only `Rainfall_3Day` — **no machine learning** —
already achieves 99.84% accuracy on this dataset:

```python
if rainfall < 150:   "Low"
elif rainfall < 200:  "Medium"
elif rainfall < 350:  "High"
else:                 "Extreme"
```

Feature importance from the trained Random Forest confirms this:
`Rainfall_3Day` accounts for **85.6%** of the model's decision-making;
`City`, `Avg_Temperature`, `Avg_WindSpeed`, and `Elevation` combined account
for the remaining ~14%. Class value ranges for `Rainfall_3Day` are almost
non-overlapping (Low: 0–148.8mm, Medium: 100.1–236.1mm, High: 200.2–361.4mm,
Extreme: 352.9–527.9mm), with overlap confined to narrow bands between
adjacent classes.

This strongly suggests `Flood_Risk` in this dataset was generated by a
rule applied during data preparation, rather than being derived from
observed historical flood outcomes. **This is the primary limitation of
this evaluation** (see §6).

### 3.3 Ruled out: train/test leakage

Two checks were run specifically to rule out leakage as the cause of the
high scores:

- **Exact duplicates**: only 44 of 44,226 test rows (0.1%) are exact
  duplicates of training rows — negligible.
- **Temporal/rolling-window overlap**: `Rainfall_3Day` is a rolling 3-day
  window, and the provided train/test split interleaves days for the same
  city (e.g. train has Jan 1/2/3/4/7, test has Jan 5/6/8/13/16 for the same
  city), which could leak signal between adjacent days. To test this
  directly, the data was re-split chronologically per city (earliest 70% of
  each city's date range → train, latest 30% → test), which eliminates the
  overlap entirely. **Result: accuracy remained 99.9%+.** Leakage is not a
  meaningful contributor to the high scores — the dataset's label really is
  this closely tied to rainfall.

### 3.4 Class-balanced sample weighting

Training can optionally apply balanced sample weights
(`sklearn.utils.class_weight.compute_sample_weight`) so rare classes aren't
drowned out by "Low" during training. This has minimal effect on Random
Forest/XGBoost (already comparatively robust to the imbalance) but a large
effect on LightGBM specifically: without it, LightGBM's ROC-AUC collapses to
~0.51-0.85 (near-random ranking ability on minority classes) despite still
scoring ~99% weighted accuracy; with it, ROC-AUC recovers to ~0.9999. This
is a useful illustration, in itself, of how weighted accuracy alone can mask
a real difference in class-handling quality between algorithms.

## 4. Where the models actually add value: the boundary zone

If accuracy is largely explained by a simple rainfall threshold, what is
the trained model actually contributing? To test this, test rows were
isolated to a "boundary zone" — within 15mm of one of the three
classification thresholds (150/200/350mm), where a trivial rule is
genuinely guessing:

| | Accuracy in boundary zone (122 rows) | Errors |
|---|---|---|
| Trivial rainfall-only rule | 68.9% | 38 / 122 |
| **Random Forest (trained)** | **95.9%** | **5 / 122** |

Outside the boundary zone (99.7% of the data), both approaches score
~99.9% — the cases are unambiguous either way. **The trained model's real
contribution is concentrated in the ~0.3% of ambiguous cases**, where it
uses `City`, `Avg_Temperature`, `Avg_WindSpeed`, and `Elevation` as
tie-breakers and cuts the error rate by ~87% relative to a naive threshold.

This is the headline result to lead with — not the 99.9% overall accuracy.

## 5. Per-class performance (Random Forest, best model)

| Class | Precision | Recall | F1 | Support (test) |
|---|---|---|---|---|
| Low | 100.0% | 100.0% | 100.0% | 44,006 |
| Medium | 98.1% | 88.8% | 93.3% | 179 |
| High | 89.2% | 97.1% | 93.0% | 34 |
| Extreme | 100.0% | 85.7% | 92.3% | 7 |

`Extreme` and `High` have very few test examples (7 and 34 respectively),
so these figures carry meaningful statistical uncertainty — one or two
additional misclassifications would shift recall noticeably. This should be
stated as a limitation rather than smoothed over.

## 6. Limitations (for the dissertation)

1. **Label provenance**: `Flood_Risk` appears to be derived from a
   rainfall-threshold rule rather than observed historical flood outcomes.
   The model comparison in this work measures how well each algorithm
   recovers that rule (and resolves its boundary ambiguity), not how well
   it predicts real-world flooding from first principles. Future work
   should validate against a dataset labelled from actual flood incident
   records.
2. **Class imbalance / small minority-class samples**: `Extreme` has only
   15 total examples across the full dataset (8 train / 7 test). Reported
   metrics for this class should be treated as indicative, not statistically
   robust.
3. **Feature scope**: the model does not currently use real-time river
   water level as an input feature, despite the system separately
   collecting `river_data`. Incorporating it would require resolving the
   incomplete river-station-to-city mapping in the existing data pipeline.

## 7. Suggested framing for the results section

> "All three models achieve high weighted accuracy (99%+), which is
> substantially explained by class imbalance and a near-deterministic
> relationship between 3-day rainfall and the provided flood-risk label
> (a rainfall-only threshold rule alone achieves 99.84% accuracy). We
> therefore report macro-averaged metrics and a targeted evaluation on
> ambiguous boundary cases as the primary basis for model comparison. Under
> this evaluation, Random Forest achieves the best macro-F1 and reduces
> classification error in ambiguous cases from 31% (naive threshold) to 4%,
> demonstrating that the additional features (city, temperature, wind
> speed, elevation) provide meaningful signal specifically where rainfall
> alone is insufficient to disambiguate risk level."
